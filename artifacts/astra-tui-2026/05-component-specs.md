# Component specifications

Baseline `dfa46a07aa43551395ba7cb6b4867ab2d8a9c324`. All dimensions are terminal cells. [Design system](03-forge-design-system.md) supplies exact palette/spacing/width/height formulas. [Agent experience](04-agent-experience.md) is authoritative for turn projection and lifecycle. Existing input routing, commands and capabilities remain unchanged.

## Shared contract

Every pane has 1-column internal padding, a 1-row title and shared separators, no outer full box. Title uses sentence case and primary/secondary text; effective keyboard owner has bold blue `>` plus blue title. Selection uses neutral background and pointer, independently of owner. No hidden pane can retain a focus marker. Modals temporarily suppress underlying focus markers. Text truncation operates on display cells, respects Unicode/graphemes and retains full underlying strings. Height formulas reserve composer and choices before decorative whitespace.

The per-component rules below inherit that contract unless an exception is explicit. Responsive behavior uses the same computed rectangles for painting, hit testing, wrapping and scroll anchors; no independent “looks right” calculations.

## Selector and dialog family

Shared modal border: one single-line rectangle, surface ground, 2-column inner horizontal padding, 1 blank row top/bottom when height permits. Modal width ≤84 and W−4; confirmations ≤64. Height is content plus chrome, capped at H−4. Start selected row visible; preserve selection/cursor on resize. Title is blue and bold with `>`. One local hint row; footer does not repeat or contradict it. Keep current modality/docking rather than making every selector a new centered overlay.

## Additional existing surfaces and scope protection

Resume/session lists, task controls, context inspection, effort/thinking controls, screenshots/attachments, external editor launch, review navigation/mark-done, subagent/background information and trust/auth screens retain their existing capabilities and fields. Apply the selector, row, notice and focus rules by family; do not remove these surfaces because the prototype's 30 core states do not enumerate every command. No new launcher, inspector, dashboard, tab bar or task workflow.

## Border inventory acceptance

At 120×35 with Files, editor and chat, only two shared vertical pane dividers appear; composer has one top rule; footer has no extra rule. Modal is the only complete rectangle. Terminal adds one top rule when open. Tree search has no rectangle. Tool payload rail appears only when expanded. Approval rail never masquerades as keyboard focus.

## Geometry acceptance

All pane bottom rectangles agree; editor mode row and last composer row share y. Terminal starts one row below the common body bottom and footer follows terminal. No pane draws into another rectangle. At 80×24 with terminal, composer and at least four transcript rows remain available. At 80×18 the primary workflow remains reachable and at least two transcript rows remain. Picker options and exact safety actions cannot be lost to offscreen padding.
